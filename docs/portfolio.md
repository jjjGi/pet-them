# 포트폴리오 / 면접 재료

면접에서 꺼낼 이야기와 수치를 모아둔다. **작업할 때마다 갱신한다.**

규칙 하나: **측정한 것과 측정하지 않은 것을 섞지 않는다.** 아래 수치는 전부 실제로 나온 것이고,
미검증 항목은 따로 모아뒀다. 면접에서 단서를 붙여 말하는 쪽이 안 붙이는 쪽보다 세다.

---

## 한 줄

> 모바일 서바이버 게임을 만들면서, **전투 규칙을 게임 엔진에서 완전히 떼어냈습니다.**
> 그래서 같은 코드가 Unity, .NET 봇 시뮬레이터, 헤드리스 검사, 그리고 서버에서 똑같이 돕니다.

---

## 1. 핵심 아키텍처 — 제일 자랑할 것

### 문제

Unity 게임은 보통 전투 로직이 엔진에 얽혀 있다. `MonoBehaviour.Update()`, `Rigidbody2D`,
`Physics2D.OverlapCircle`, 프레임레이트 의존. 그러면 이런 게 전부 불가능하다.

- 에디터 없이 규칙을 테스트하는 것
- 봇으로 수천 판을 돌려 밸런스를 재는 것
- **서버가 전투 결과를 검증하는 것**

### 접근

전투 규칙 전체를 **UnityEngine 의존성이 0인 netstandard2.1 라이브러리**로 분리했다.
(`packages/com.petthem.combat-core`)

- `UnityEngine.Vector2` 대신 자체 `Vec2`
- **고정 스텝 1/60초.** 프레임레이트와 무관
- 시드 결정론. 같은 시드 + 같은 입력 = 항상 같은 결과
- 입력 하나(`PlayerInput`)를 넣으면 이벤트 스트림이 나온다

### 결과

**같은 코드가 네 군데서 돈다.**

| 어디 | 무엇 |
|---|---|
| Unity | 게임 |
| .NET 봇 시뮬레이터 | 밸런스 측정 |
| `tools/CoreChecks` | 검사 53개, 에디터 없이 몇 초 |
| `server/PetThem.Server` | 판 가격 산정, (예정) 리플레이 검증 |

### 대가도 같이 말할 것

`Vec2`를 직접 만들어 쓰는 건 확실히 어색하다. 그 어색함이 위의 네 칸을 산 값이다.
**"편한 길을 알면서 안 갔고, 그 대가로 뭘 얻었는지 안다"**가 이 이야기의 핵심이다.

## 2. 면접에서 꺼낼 이야기 (문제 → 접근 → 결과)

### ★ 이빨 없는 테스트를 발견한 것

**제일 추천.** 테스트 품질에 대한 이야기라 직군을 안 탄다.

- **문제**: 보스를 잡은 뒤에 화면에 "보스가 옵니다" 경고가 떴다.
- **원인**: `SecondsToBoss`가 `Math.Max(0, spawnTime - Time)`이라 **보스 등장 후 판이 끝날 때까지
  0이다.** "12초 이하면 경고"는 1분 전에 죽은 보스에도 참이었다.
- **1차 수정**: 두 겹으로 막고 회귀 검사를 썼다. 통과.
- **여기서 멈추지 않았다**: 방어 코드를 빼고 다시 돌려봤다. **여전히 통과했다.**
  검사가 100스텝을 돌린 *뒤에* 확인하는데, 잘못 뜬 경고는 8초면 저절로 사라져서
  검사가 볼 때는 이미 정상으로 돌아와 있었다.
- **결과**: 매 스텝 확인하도록 고쳤고, **방어를 빼면 실패하는 것을 확인**한 뒤 커밋했다.

> **교훈**: 통과하는 테스트가 아니라, **버그를 다시 넣었을 때 실패하는 테스트**여야 한다.
> 그걸 확인하는 건 30초 걸린다.

### ★ 단위 테스트가 못 잡고 실측이 잡은 크래시

- **문제**: 폭발 강화를 추가한 뒤 봇을 12판 돌리다 예외로 죽었다.
- **원인**: 무기 루프가 `for (int i = enemies.Count - 1; i >= 0; i--)`로 역순 순회하면서
  **"피해를 주면 적 하나만 사라진다"**를 전제하고 있었다. 그동안은 맞았다.
  폭발은 한 번에 여러 마리를 지운다 → 목록이 인덱스보다 빨리 줄어 범위 이탈.
  **펀치·레이저·화살·구슬·접촉 피해 루프가 전부 해당됐다.**
- **접근**: 목록 복사본을 순회하고 이미 죽은 적은 건너뛴다.
  버퍼는 **호출 지점마다 따로** 뒀다 — 폭발은 다른 루프의 `Damage` 안에서 일어나므로
  버퍼를 공유하면 바깥 루프의 것을 덮어쓴다.
- **결과**: 회귀 검사로 고정.

> **교훈**: 검사 43개가 통과하고 있었다. **실제로 돌려본 프로그램이 잡았다.**
> 단위 테스트는 "내가 생각한 경우"만 본다.

### ★ null이 아닌 것을 "쓸 수 있다"로 읽은 것

- **문제**: 실기기 APK에서 **글자가 전부 사라졌다.** 한글이 네모로 깨진 게 아니라
  버튼 라벨과 영어까지 전부. 레이아웃·스프라이트·배경은 정상.
- **원인**:
  ```csharp
  Font glyphs = Font.CreateDynamicFontFromOSFont(new[] { "Malgun Gothic", ... }, 32);
  if (glyphs != null) title.font = ... = glyphs;   // null 검사만 했다
  ```
  Android에는 저 이름이 하나도 없는데 **호출은 null이 아닌 Font 객체를 돌려준다.**
  그 객체는 아무 글자도 못 그린다. 그걸 모든 스타일에 씌워서 영어까지 같이 죽었다.
- **접근**: 기기에 **실제로 있는** 폰트 이름을 먼저 묻고(`GetOSInstalledFontNames`),
  만든 폰트가 `HasCharacter('A')`와 `HasCharacter('가')`를 **실제로 통과하는지 증명한 뒤에만** 쓴다.
  - 한글이 안 되고 라틴만 되면 → 그 폰트를 쓰되 **한국어를 끄고 영어로 전환**한다.
    읽을 수 없는 언어를 선택지로 두지 않는다.
  - 전부 실패하면 → **내장 폰트를 그대로 둔다.** 한글은 없지만 영어는 나온다.
  - 시작 화면에 어떤 폰트를 골랐는지 찍는 진단 줄을 넣었다. **내장 폰트로 그려서**,
    고른 폰트가 아무것도 못 그려도 그 줄만은 읽힌다.
- **결과**: 사용자 실기기 확인 — 한글 정상 출력.

> **교훈**: `null`이 아니라는 것은 "쓸 수 있다"가 아니다.
> 그리고 실패는 **"아무것도 없음"이 아니라 "읽을 수 있는 실패"**여야 한다.

### 서버가 가격을 매긴다

- **문제**: 클라이언트가 "코인 460 주세요"라고 보내면 서버는 믿을 방법이 없다.
- **접근**:
  - 판 제출 페이로드에서 **코인 필드를 아예 뺐다.** 클라는 "88킬, 74.5초, 보스 못 잡음"만 말한다.
  - 보상 공식을 코어의 `CombatWorld.CoinsFor` **하나로** 만들었다.
    결과 화면이 보여주는 숫자와 서버가 지급하는 숫자가 같은 함수에서 나온다.
    서버에 공식을 두 번째로 쓰면 반드시 어긋난다.
  - 판의 **이변(난이도 변형)은 클라에게 묻지 않는다.** 이변은 시드에서 굴러 나오고
    코인 수치 자체를 곱하므로, 서버가 시드로 판을 다시 만들어 그 판의 설정을 직접 읽는다.
- **결과**: 전투에 대해 거짓말해도 **임의의 금액이 되지는 않는다.**
- **정직하게 붙일 말**: 처치 수와 시간은 아직 클라의 말이다. 서버가 거르는 건 모양뿐이다
  (음수 처치, 3분을 넘긴 3분 판, 없는 무기). **리플레이 검증이 닫을 구멍**이고 코드와
  README에 그렇게 적었다.

### 같은 판으로 두 번 못 받는다 (멱등성)

- **문제**: 업로드 도중 신호가 끊긴 폰은 같은 판을 다시 보낸다. 여러 번 보낼 수도 있다.
- **접근**: `IProfileStore`를 불러오기/저장하기 쌍이 아니라 **트랜잭션 경계**로 설계했다.
  "이 판이 이미 계산됐나, 아니면 코인을 더하고 계산됨으로 표시" — 세 단계가 다른 요청과
  엇갈리면 안 된다. 프로필을 꺼내 주고 엔드포인트가 조립하게 했으면
  이 불변식이 엔드포인트마다 흩어진다.
- **결과**: 3번 보내도 코인은 1회분, `runsFinished`는 1. 검사로 고정.
  인메모리 구현과 DB 구현의 차이가 **잠금이냐 트랜잭션이냐**뿐이고, 그 위 코드는 안 바뀐다.

### 기본값을 뒤집지 않은 것

- **문제**: 판마다 난이도 변형(이변)을 넣으면 **기존 검사 49개와 봇 전부의 수치가
  조용히 무의미해진다.** 전부 이변 없는 조건으로 작성됐기 때문이다.
- **접근**: `enableTwists` 기본값을 `false`로 두고 **게임만 `true`를 넘긴다.**
  그리고 **그 기본값 자체를 검사가 고정한다** (시드 40개가 전부 `Calm`이어야 한다).
- **결과**: 새 기능이 기존 측정값을 오염시키지 않는다.

> 라이브러리에 기능을 추가할 때 기본 동작을 바꾸지 않는 것, 그걸 테스트로 못 박는 것.

### 난수 스트림을 분리한 것

크리티컬을 굴렸다고 적 등장 위치나 다음 강화 카드가 달라지면 재현성이 깨진다.
**독립 스트림 5개**(스폰 / 성장 / 효과 / 보스 / 이변)를 쓴다.
크리티컬 확률을 조정해도 같은 시드의 스폰·카드·보스 기술 순서가 그대로다.

### 화면과 실제가 어긋날 수 없게 만든 것

활 게이지, 조준 미리보기, 실제 발사가 **`CombatWorld.DrawPower` 같은 함수**를 쓴다.
"게이지가 60% 찼는데 약하게 나갔다"가 구조적으로 불가능하다.

같은 원칙으로, 펀치 이펙트 링을 실제 사거리와 일치시켰다. 이전에는 보이는 원보다 판정이 넓었다.

## 3. 수치

### 측정된 것

| | |
|---|---|
| 자동 검사 | 게임 **53** + 서버 **9** + 실험실 회귀 **14** |
| Unity 소스 컴파일 | 경고 **0** / 오류 **0**, 실제 Unity DLL 참조, **에디터를 열지 않고** |
| 렌더러 수 (적 100마리) | **500 → 100** (생물 하나 = 렌더러 하나, 얼굴·귀를 텍스처에 구움) |
| APK 크기 | 개발 빌드 **31.2 MiB** / 릴리스 **16.7 MiB** |
| ㄴ 차이의 원인 | `libunity.so` **24.0 MB → 11.4 MB** (프로파일러·디버그 심볼) |
| 결정론 | 시드 42~46 이벤트 스트림이 저장소 이관 전후 **바이트 단위 동일** |
| 봇 측정 | 이변 6종 × 각 10판 (생존 시간·처치·코인·승패 분포) |

### 측정되지 않은 것 — 말할 때 반드시 붙일 단서

- **봇은 펀치만 쓴다.** 화살·레이저 밸런스는 봇으로 평가할 수 없다.
- **레이저 봇 수치는 무효다.** 봇이 조준 벡터를 주지 않아 빔이 오른쪽에 고정된 채 싸운다.
  (레이저는 의도적으로 자동 조준이 없다.)
- **화살 봇의 보스전 전패는 밸런스 근거가 아니다.** 봇이 경기장 구석에 박혀서 생긴 것이다.
- 렌더러 감소가 **실제 프레임 향상으로 이어지는지 측정하지 않았다.** 계산상 5분의 1이다.
- **Unity(IL2CPP ARM64)와 .NET(x64)의 전투 결과 대조를 하지 않았다.**
  리플레이 검증이 전적으로 여기 걸려 있다.

> 이 목록을 그대로 말하는 것이 강점이다. "봇으로 밸런스 맞췄습니다"보다
> "봇이 답할 수 있는 질문과 없는 질문을 구분했습니다"가 세다.

## 4. 코드에서 보여줄 곳

| 파일 | 왜 |
|---|---|
| `packages/com.petthem.combat-core/Runtime/CombatWorld.cs` | 엔진 없는 전투 코어. 고정 스텝, 시드 결정론 |
| `packages/com.petthem.combat-core/Runtime/CombatStage.cs` | `CoinsFor` — 게임과 서버가 공유하는 단 하나의 보상 공식 |
| `server/PetThem.Server/ProfileStore.cs` | 트랜잭션 경계로 설계한 저장소 인터페이스 |
| `server/PetThem.Server/Contracts.cs` | 코인 필드가 **없는** 판 제출 페이로드 |
| `server/PetThem.ServerChecks/Program.cs` | 실제 서버를 띄워 진짜 HTTP로 때리는 검사 |
| `game/Assets/Scripts/PrototypeGame.cs` `ResolveFont()` | 폰트 대체 — 실패를 읽을 수 있게 만든 코드 |
| `game/Assets/Scripts/Coach.cs` | 튜토리얼도 UnityEngine 없이 → 발동 조건을 검사로 고정 |
| `game/Assets/Scripts/Texts.cs` | 화면 문자열 단일 출처. 번역 누락을 검사가 잡는다 |

주석을 "무엇"이 아니라 **"왜 이렇게 했는가"**로 썼다. 열어서 보여줄 수 있다.

## 5. 정직하게 말할 약점

면접에서 먼저 꺼내는 편이 낫다.

- **리플레이 검증은 아직 없다.** 하겠다고 정했고, 그 전에 float 결정론 측정이 먼저다.
- **로그인이 게스트뿐이다.** 신원 확인이 없다.
- **저장이 메모리뿐이다.** 프로세스가 죽으면 사라진다.
- **클라이언트가 아직 서버를 호출하지 않는다.**
- **손맛을 사람이 거의 확인하지 못했다.** 확인된 건 한글 표시와 소리, 코치 가독성뿐이다.
- MCP와 밸런스 실험실은 **의도적으로 보류**했다. 게임 완성이 먼저라고 판단했다.

## 6. 아직 안 했지만 하면 재료가 되는 것

- **결정론 측정** — 갈라지면 고정소수점 전환/허용오차/서버 정본 재생 중 선택.
  결과가 어느 쪽이든 이야기가 된다.
- **리플레이 검증** — 탕탕특공대는 클라를 믿고 밴 웨이브로 간다.
  *왜 그들이 그렇게 하는지 알면서* 다른 선택을 하는 것이 포인트.
- **게스트 → 계정 전환** — 게스트로 코인 460을 모았는데 로그인한 계정엔 이미 1200이 있다.
  합칠까, 덮을까, 고르게 할까. **관리형 서비스가 안 풀어주는 문제**다.
- **텔레메트리 수집** — 이미 기록은 남고 있는데 기기 안에서 죽는다.
- **원격 밸런스 설정** — 2KB JSON. 스토어 심사 없이 밸런스 조정.
