## 2026-09-20 — 0.15.0 첫 30초 코치

PROJECT.md의 다음 작업 1순위였다. 게임에 설명이 사실상 없었고, 특히 활 당기기는
`arrowMinDraw` 미만으로 당기면 **아무 일도 일어나지 않는데 왜인지 말해 주는 것이 없었다.**

- **`Coach.cs` 신설.** 수업 다섯: 이동(3m) / 공격(무기별 3종, 3처치) / 당기기(활 전용) /
  강화(첫 선택 후 6초) / 보스(등장 12초 전, 8초간).
- **판을 멈추지 않는다.** 닫을 것도 없고, 아는 사람은 플레이만으로 다 통과하고 한 글자도 안 읽는다.
- **당기기 수업이 핵심이다.** 발사 안 된 당김 판정에 `world.DrawPower(drawAmount) <= 0`을 쓴다.
  실제로 화살을 쏘는 그 함수라 코치의 판단과 실제 결과가 어긋날 수 없다.
  한 번은 실수로 넘기고 두 번째에 뜬다. 이 수업만 이동 수업보다 우선한다.
- **전투 코어를 건드리지 않았다.** 대본 구역도 순한 첫 웨이브도 없다.
  봇이 재는 게임과 플레이어가 배우는 게임이 같아야 하기 때문이다. 실험실 회귀 검사 불필요.
- `Texts.cs`·`PlayerProfile.cs`처럼 UnityEngine 비의존이라 `tools/CoreChecks`에 넣어 검사한다.
  새 검사 4개 + 번역 검사에 `CoachLine`(수업 × 무기 전부) 추가.
- 저장은 `PlayerPrefs`의 `coach.learned` 비트마스크. **수업이 끝나는 순간 저장한다.**
  첫 전투 도중 폰을 내려놓은 사람이 다시 켰을 때 걷는 법부터 듣지 않게 하려는 것이다.
- 시작 화면에 `조작 다시 배우기`. 하나라도 배웠으면 나온다(보스 수업은 2분을 버텨야 끝나므로).
- **작업 중 버그 하나를 잡았다.** `SecondsToBoss`는 보스 등장 후 판이 끝날 때까지 0이라,
  "12초 이하면 경고"만으로는 **보스를 잡은 뒤 시체 위에 경고가 뜬다.** 두 겹으로 막았다:
  게임이 `BossDefeated`도 넘기고, 코치가 `secondsToBoss > 0`을 추가로 요구한다.
  처음 쓴 회귀 검사는 100스텝 *뒤에* 확인해서 이 버그를 못 잡았다(잘못 뜬 경고는 8초면 사라진다).
  지금은 매 스텝 확인하고, 방어를 빼면 실패하는 것을 확인했다.
- 검사 53개 통과, Unity 소스 컴파일 경고 0 · 오류 0. **0.15.0 APK 빌드 완료.**

**수업이 실제로 읽히는지는 아무도 모른다.** 화면 아래쪽 가운데 680×58 상자에 한 줄로 그린다.
적이 몰린 상황에서 묻히는지, 문장이 두 줄을 넘쳐 잘리는지는 폰에서 봐야 한다.
영어 공격 수업(활)이 71자로 가장 길다. 자세한 내용은 [verification.md](verification.md) 0.15.0 절.

## 2026-09-20 — 0.14.0 이변과 웨이브 구성

사용자가 "판마다 똑같이 반복된다"는 지적에 따라 고른 항목이다.

- **웨이브마다 적 구성이 달라진다.** 1웨이브에는 브루트가 없고, `mixWaves`(5)에 걸쳐 최종 비율까지 올라간다.
  이전에는 웨이브가 올라가도 스폰 속도와 체력만 변했다. `runnerShare`·`mixWaves` 설정 추가.
- **`CombatTwist.cs` 신설.** 판마다 이변 6종 중 하나가 정해진다(평범한 날 / 우글우글 / 발 빠른 무리 /
  단단한 껍질 / 이른 방문 / 매서운 이빨). 어려울수록 코인을 더 준다.
- **`enableTwists`는 기본 false다.** 검사 49개와 봇 전부가 이변 없는 수치로 작성됐기 때문이다.
  게임만 `true`를 넘긴다. 이 기본값 자체를 검사가 고정한다.
- 이변은 `twistRandom` 독립 스트림. 화면에는 판 시작 5초 배너 + 일시정지 화면에 표시.
  기록(`run_start`)에 `twist` 필드 추가 — 어떤 조건의 판인지 모르면 분석이 무의미하다.
- **화살 미리보기가 캐릭터를 따라간다.** 사용자 보고 버그. 손가락 좌표에 고정돼 있던 방향 표시를
  캐릭터 위치에서 `world.Facing` 방향으로 그리도록 바꿨다. 조작부(고리·시위·게이지)는 엄지 밑에 그대로.
- 검사 49개 통과, Unity 소스 컴파일 경고 0 · 오류 0.

**지켜볼 것: 우글우글이 코인을 25% 더 주면서 펀치 봇에게는 가장 쉽다.**
무기에 따라 갈리는 것이라면 의도한 설계지만, 봇은 펀치만 써서 답을 못 낸다.
활·레이저로 우글우글을 해 봐야 안다. 자세한 수치는 [verification.md](verification.md) 0.14.0 절.

## 이전 수정 (0.13.0) — 소리

Codex가 커밋 전에 멈춘 작업을 이어받아 마감했다. 코드는 Codex가 썼고, 검증·문서·커밋만 했다.

- `game/Assets/Scripts/GameAudio.cs` 신설. **모든 소리를 코드로 합성한다.**
  내려받은 음원이 없으므로 라이선스 문제가 없다. 아트(`Art.cs`)와 같은 방침이다.
- 배경음악: 120 BPM 8마디 루프를 `Compose()`가 생성한다. 펜타토닉 멜로디 + 베이스 + 킥 + 하이햇.
  전투 중이 아니면 볼륨이 줄고, 보스가 있으면 피치가 1.12배로 올라간다.
- 효과음 9종(펀치·화살·펫·드론·피격·강화·보스 예고·승리·패배)과 레이저 루프.
  같은 소리는 0.08초 안에 다시 나지 않는다. 적이 몰릴 때 소리가 뭉개지는 것을 막는다.
- 켜고 끄기는 `PlayerPrefs`에 남는다. 시작 화면 버튼 두 개(`배경음악` / `효과음`).
- 앱이 포커스를 잃거나 백그라운드로 가면 음악을 멈춘다. 모바일에서 필요한 처리다.
- 같이 들어온 시각 변경: **공격 앞발**(`attackPaw`)이 생겼다. 펀치는 앞으로 뻗고,
  활은 당기는 동안 뒤로 당겨진다. 작은 화면에서 공격이 읽히게 하려는 것이다.
- 검사 46개 통과, Unity 소스 컴파일 경고 0 · 오류 0.

**소리는 아무도 들어본 적이 없다.** 합성 음원이라 실제로 어떻게 들리는지는 기기에서 확인해야 한다.
음악이 거슬리는지, 효과음이 시끄러운지, 8마디 루프가 3분 동안 질리는지는 사람이 판단할 일이다.

## 가장 중요한 사용자 지시

**게임을 먼저 다 만들고, MCP는 그 뒤에 진행한다.**
사용자는 기존 Unity 화면·조작을 확인했다고 답변했다. 기존 화면 확인 대기는 끝났다.
MCP 기능 추가·보고서·분석 실험을 다음 작업으로 잡지 않는다.

## 사용자가 아직 플레이하지 못한 것 — 돌아오면 반드시 안내한다

사용자가 명시적으로 요청한 사항이다. 아래를 **항목별로** 테스트해 달라고 말한다.
"확인했어"는 그 시점 빌드에 대한 것이므로, 이후 추가분까지 확인한 것으로 간주하지 않는다.

1. **강화 선택 화면 (0.2.0)** — 처치 5회 / 약 9초면 뜬다. 사용자가 확인한 빌드에는 없었다.
2. **무기 3종 (0.3.0)** — 펀치·화살·레이저. 화살 조작은 0.9.0에서 바뀌었다(아래 9번).
3. **보스 (0.4.0)** — 120초 등장. 붙었다 빠지는 리듬이 되는지. 레이저로 잡히는지.
4. **펫 3종 (0.5.0)** — Bori의 감속이 눈에 보이는지, Coco의 회복 주기가 답답하지 않은지.

## 다른 PC에서 테스트하려면

게임 저장소만 있으면 된다. 실험실 저장소는 필요 없다.

1. `git clone https://github.com/jjjGi/pet-them` — **저장소 전체**를 받는다.
   `game/Packages/manifest.json`이 `file:../../packages/com.petthem.combat-core`를 참조하므로
   game 폴더만 복사하면 열리지 않는다.
2. Unity Hub에서 Unity **6000.3.24f1** 설치. Android까지 보려면 Android Build Support도 함께.
3. Unity 계정 로그인 후 Personal 라이선스 활성화.
4. Hub에서 저장소 안의 **game** 폴더를 프로젝트로 추가.
5. 메뉴 **PET THEM > Create or open prototype scene** → Play.

.NET SDK는 검사를 돌릴 때만 필요하고 플레이에는 필요 없다.
저장 파일과 플레이 기록은 기기별로 따로 생기므로, 다른 PC에서는 코인이 0부터 시작한다.
