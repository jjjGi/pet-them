## 2026-09-28 — 모바일 플레이 크기로 캐릭터 검토

- 기존 Unity 숲 렌더로 현재 고양이 크기를 제시하고 P1/P4/P5/P7의 전투 화면 예상 시안을 생성한다. 예상 시안은 실제 게임 캡처·실행 검증과 구분한다. 아직 플레이어 선택이나 에셋 교체는 없다.
- 결과물: [모바일 화면 시안](concepts/mobile-gameplay.md). 최초 생성의 캐릭터가 코드상의 크기보다 크게 나와 축소 수정 요청. 생성 이미지의 배율을 정확한 런타임 배율로 보고하지 않는다.

## 0.21.0 최신 작업 — 탐험 보상·조합 진화 / 아트 선택 대기

- 사용자가 후보 1(탐험 보상), 3(무기·펫 진화)를 승인했다. 위험 이벤트는 구현하지 않았다.
- 공유 코어 `CombatAdventure.cs`: 한 판 최대 3상자. 12m 거리의 상자에 접근하면 강화 XP + 다시 뽑기 1회 + 체력 15% 회복. 다음 상자는 20초 후 생성. 강화 화면 동안 시간 정지, 중복 수령 방지. 최대 레벨에서는 XP 없음.

- 설정 버전 `prototype-0.6-adventure`, 앱 `0.21.0`. 코드 기본 adventureEnabled=false, 게임 JSON=true. 기존 봇 결과를 새 재미의 근거로 쓰지 않는다.

- Unity 배치 `PetThem.Editor.AdventureValidation.Verify`로 상자·추가 공격 3종을 렌더하고 확인했다(experiments/adventure-preview). 합성 장면이며 HUD와 실제 플레이 검증은 아니다.

- 실제 플레이의 상자 안내·재료 선택·진화 체감·모바일 UI 확인이 필요하다. 새 APK 미빌드. 아래 서버 전체 플레이 경로 미검증도 유지한다.

## ▶ 지금 막혀 있는 것 — 실제 판 종료부터 자동 전송까지는 미검증

- 사용자 최신 요청은 맵 종류 확대와 재미 요소 제안. 0.20.0에서 기존 숲·사막·설원에 벚꽃 정원·버섯 습지·수정 동굴을 추가했다. 홈에서 2행 3열로 선택하고 저장한다. 현재는 시각 테마 6종이며 맵별 전투 규칙·보상 차이는 없다.
- **UnityWebRequest 미실행은 해소했다.** 실제 Unity 배치 에디터와 별도 SQLite 서버를 함께 실행했다. ServerLink의 실제 Post 생성 메서드로 세션 생성 HTTP 200 → 가상 판 제출 HTTP 200 → 같은 판 재제출 HTTP 200/alreadyCounted를 확인했다.
- 이 검사는 게임의 BankRun → 파일 큐 → Update/코루틴 전체를 통과하지 않는다. 실제 플레이의 자동 전송, 재시작 후 큐 복구, Android 통신은 여전히 확인해야 한다. 테스트는 사용자 PlayerPrefs·실제 outbox를 수정하지 않는다.
- 재현: Unity가 닫힌 상태에서 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-unity-transport.ps1`. 실행 중인 Unity가 있으면 종료시키지 않고 검사를 거부한다. 검사 전용 5165 포트와 experiments/ 안의 별도 DB를 사용하며 자신이 띄운 프로세스만 정리한다.
- 다음 재미 후보(미구현): 탐험 중 보상 발견 → 위험 구역에서 잠시 버티고 보상 선택 → 무기와 펫 조합에 따른 진화. 현재 이동 목적이 약하다는 가설이며 실제 재미 향상은 플레이로 확인해야 한다.
- 공통 전투 코어·밸런스는 변경하지 않았다. MCP 확장은 계속 보류.
- 최종 검사: `scripts/check.ps1` 게임 68/서버 14 통과, Unity 소스 경고 0/오류 0. Unity 맵 렌더 6종·30청크/200회 이동 검사 통과. 이번 Android APK는 미빌드.

흰 섬광(0.09초) + 피해 숫자(0.62초 떠오르며 사라짐). 크리는 크고 노란색이다.
**코어 변경 없음** — `damage` 이벤트가 이미 대상 id·실제 피해량·위치·크리 여부를 다 담고 있었다.

### ★ 결정론 측정 — 이 저장소에서 제일 중요한 측정

PROJECT.md에 처음부터 미검증으로 있던 항목. **리플레이 검증 전체가 여기 걸려 있었다.**

| | 결과 |
|---|---|
| 한 판(3분) 모든 이벤트 | **977 / 3,202 줄 다름 (30%)** |
| 40판 처치 수 | **40 / 40 일치** |
| 40판 코인 | **38 / 40 일치** (2판 1코인 차) |

- ❌ **완전 일치 검증은 불가능하다.** 정직한 플레이어를 거절하게 된다.
- ✅ **허용오차 검증은 된다.** 필요한 오차가 작다(±1코인 수준).
- **폰(IL2CPP/ARM64)은 아직 못 쟀다.** PC 두 런타임(.NET x64 / Unity 에디터) 비교다.

**내 가설이 틀렸다.** `Math.Sin`/`Cos`를 범인으로 봤는데, 23틱까지 완전 일치였고
Sin/Cos를 쓰는 첫 스폰도 비트까지 같았다. 첫 차이는 `Vec2.Normalized`의 `sqrt(x*x + y*y)`다.

되풀이: `powershell -File scripts/determinism.ps1` (양쪽 전사 생성 + 대조까지 한 번에)

### ★★ 재다가 서버 버그를 잡았다 — 서버가 엉뚱한 밸런스로 돌고 있었다

`System.Text.Json`은 **public 필드를 읽지 않는다.** `BalanceConfig`는 Unity `JsonUtility`에
맞춰 전부 public 필드라, **서버가 balance-default.json을 통째로 무시하고 코드 기본값으로
판 가격을 매기고 있었다.**

**서버 검사 13개가 못 잡은 이유**: 검사도 기댓값을 `new BalanceConfig()`로 만들었다.
**양쪽이 똑같이 틀려서 서로 동의했다.**

고친 것: ① `IncludeFields = true` ② `/health`가 로드한 밸런스 버전을 보고
③ 검사가 기댓값을 **파일에서** 만들고 **시험 대상을 공유하지 않는다**.
서버 검사 13 → **14개**.

**같은 라이브러리의 같은 실수를 두 번 했다**(클라 계약 검사 때 한 번). 주석에 못 박았다 —
**BalanceConfig가 System.Text.Json을 지나갈 때는 `IncludeFields`가 필요하다.**

에디터 어셈블리가 `PetThem.Combat`을 참조하지 않아 실제 Unity 컴파일이 깨졌는데 검사는 통과했다.

## 2026-09-24 — 0.19.0 피격 표현·밀어내는 숨·등급 색·다시 돌리기

카드 풀이 바뀌었으므로 이전 버전과 밸런스 수치를 직접 비교하지 않는다.

등급 색과 테두리 두께가 실제로 구분되는지, 다시 돌리기 2회가 적당한지.

## 실제 플레이의 서버 연동 확인 절차 (0.20.0 상태 반영)

**Unity의 실제 HTTP 호출은 0.20.0 자동 검사에서 확인했습니다. 실제 플레이 자동 전송은 미검증입니다.**

서버(`server/`)도 있고 클라이언트 전송 큐(`RunOutbox`, `ServerLink`)도 있고
양쪽 검사도 통과합니다. 0.20.0에서는 둘을 함께 실행하여 가상 판 제출과 중복 처리를 확인했습니다.
게임에서 끝낸 판이 큐에 쌓이고 자동 전송되는 전체 과정은 아직 확인하지 않았습니다.

자동 통신 검사와 실제 플레이 확인을 구분합니다. 아래는 사용자가 직접 확인하는 절차입니다.

### 확인 절차

1. 터미널에서 `dotnet run --project server/PetThem.Server`
   → `Now listening on: http://localhost:5164`. 창은 켜둔 채로.
2. Unity 에디터에서 Play.
3. **설정 탭** → 서버 주소칸에 `http://localhost:5164` → **적용**.
4. **판을 끝까지 합니다.** ← 제일 중요
5. 결과 화면 → 홈으로 → 설정 탭에서 확인:
   - `보낼 판 0개` + `마지막 전송: 성공` → 됐다
   - 실패 메시지가 뜨면 그 문구가 곧 진단이다

### 함정 세 개

1. **중도 종료(abandoned)는 큐에 안 들어갑니다.** 업로드를 `BankRun()`에서 거는데
   그게 승리/패배일 때만 돕니다(중도 종료는 코인도 안 주는 기존 규칙).
   **"잠깐 해보고 끄기"로는 절대 확인이 안 됩니다.** 빨리 죽는 법: 공격하지 말고

2. **Android 9+ 는 평문 `http://`를 기본 차단합니다.** 폰에서 LAN 주소로 붙이려면

## 2026-09-21 — 0.17.1 검사가 거짓 통과를 준 건

`UnitySourceCheck`가 Unity 모듈 폴더를 **와일드카드로** 참조해서, 프로젝트가 꺼둔 모듈의 API에도
"컴파일 됩니다"라고 답하고 있었다. `UnityWebRequest`를 쓰자 검사는 통과하고 실제 빌드가 죽었다.

켜진 모듈만 이름으로 참조하게 바꾸고, `manifest.json`과 그 목록이 어긋날 수 없도록 검사를 추가했다.
**양방향으로 실패를 확인했다**(참조를 빼면 실패, 꺼진 모듈을 넣으면 실패).
`Font`·`Input`처럼 manifest에 없는데 항상 있는 엔진 기본 모듈이 있어서, 규칙은
"참조 == manifest ∪ 항상 있는 모듈"이다. 자세한 내용은 verification.md 0.17.1 절.

같이 들어온 것: **서버 주소 입력칸**(설정 탭). 그전에는 `PlayerPrefs`에만 있고
입력할 방법이 없었다. 비워두면 서버로 아무것도 보내지 않는다 — 입력칸이 곧 끄는 스위치다.

## 2026-09-21 — 0.17.0 클라 연동 (전송 큐)

서버 골격에 이어 클라이언트를 붙였다. 전제는 그대로다 —
**네트워크 없이도, 서버가 아예 없어도 게임은 그대로 돌아간다.**

- **RunOutbox.cs** 신설. 끝난 판을 파일에 쌓고 보낼 수 있을 때 보낸다.
  UnityEngine 비의존이라 CoreChecks에서 검사(6개). 게임 검사 53 → **59**.
- **핵심 판단**: HTTP 응답을 "아직 안 정해짐"(5xx·429·타임아웃 → 들고 있음)과
  "영원히 안 됨"(4xx → 버리고 이유 기록)으로 가른다. **401은 따로** — 판은 멀쩡하고
  세션이 문제라 토큰만 버린다.
- 재시도 2초 → 두 배씩 → **5분에서 멈춤**. 밤새 쌓인 큐가 아침에 즉시 나가야 한다.
- **ServerLink.cs** 신설. UnityWebRequest로 전송. `server.baseUrl`이 비어 있으면
  **이전과 완전히 동일하게** 동작한다(기본값이 비어 있음).
- **계약 검사 추가** — 서버 검사에 클라 큐 소스를 같이 컴파일해서 양쪽 페이로드를 대조.
  **첫 실행에서 버그를 잡았다**: System.Text.Json은 public 필드를 직렬화하지 않는다.
  서버 검사 9 → **10**.
- `runId`를 `RunRecorder`에서 분리했다. 기록 파일 생성이 실패하면 업로드까지 죽었다.

**로컬 저장이 아직 정본이다.** 서버는 같은 숫자를 받지만 권위는 아직 아니다 —
서버에 저장도 로그인도 없어서 권위를 넘기면 프로세스가 죽을 때마다 코인이 사라진다.

**Unity가 실제로 서버를 호출하는 것을 아무도 못 봤다.** 양쪽 검사는 통과하지만
UnityWebRequest 경로는 한 번도 실행된 적이 없다. 확인하려면 서버를 띄우고
`server.baseUrl`을 PlayerPrefs에 넣어야 한다.
자세한 내용은 [verification.md](verification.md) 0.17.0 (클라) 절.

## 2026-09-21 — 0.17.0 서버 골격 (범위 변경)

**사용자 목표가 밝혀졌다: 서버 개발자 포트폴리오다.** 클라이언트는 부가 어필이고,
수익은 부차적 목표다. 그 시점까지 저장소에 네트워크 코드가 **한 줄도 없었다.**
AGENTS.md 맨 위에 이 우선순위를 적었다. **MCP는 여전히 보류다. 서버 작업은 MCP 재개가 아니다.**

사용자가 고른 구성:

- **신원은 Play Games 로그인**(`RequestServerSideAccess` → server auth code), **정본은 내 서버**.
- **리플레이 검증을 하기로 했다.** 탕탕특공대는 안 한다(클라 신뢰 + 밴 웨이브)는 것을
  알고 고른 것이다. 게임 필요가 아니라 포트폴리오 무기다.
- Play Games Saved Games / PGS 리더보드는 **거부**했다. 공짜고 동작하지만 서버 코드가
  남지 않고, PGS 리더보드는 점수를 검증하지 않는다.
- **오프라인 플레이는 유지한다.** 광고 보상만 온라인을 요구한다.

이번에 만든 것 — `server/`:

- `PetThem.Server` (ASP.NET Core, net10.0) + `PetThem.ServerChecks` (검사 9개).
- **게임과 같은 전투 코어를 참조한다.** 보상 공식을 `CombatWorld.CoinsFor`로 코어에 빼서
  게임과 서버가 같은 함수를 쓴다. 이변은 시드에서 서버가 직접 유도한다(클라에게 안 묻는다).
- 판 제출에 **코인 필드가 없다.** 서버가 가격을 매긴다. 같은 `runId`는 한 번만 지급.
- `IProfileStore`가 트랜잭션 경계다. 지금은 메모리, DB로 바꿔도 API는 안 움직인다.
- 검사는 **실제 서버를 랜덤 포트에 띄우고 진짜 HTTP로** 때린다. 테스트 프레임워크 없음.
- 코어를 바꿨으므로 **실험실 회귀 14개**도 돌렸다. 통과.

**아직 클라이언트가 서버를 호출하지 않는다.** 게임은 로컬 저장 그대로다. 다음 작업이다.

## 다른 PC에서 테스트하려면

게임 저장소만 있으면 된다. 실험실 저장소는 필요 없다.

1. `git clone https://github.com/jjjGi/pet-them` — **저장소 전체**를 받는다.
   `game/Packages/manifest.json`이 `file:../../packages/com.petthem.combat-core`를 참조하므로
   game 폴더만 복사하면 열리지 않는다.
2. Unity Hub에서 Unity **6000.3.24f1** 설치. Android까지 보려면 Android Build Support도 함께.
3. Unity 계정 로그인 후 Personal 라이선스 활성화.
4. Hub에서 저장소 안의 **game** 폴더를 프로젝트로 추가.
5. 메뉴 **PET THEM > Create or open prototype scene** → Play.

.NET SDK는 검사를 돌릴 때만 필요하고 플레이에는 필요 없다.
저장 파일과 플레이 기록은 기기별로 따로 생기므로, 다른 PC에서는 코인이 0부터 시작한다.
