# 인계 문서

마지막 갱신: 2026-09-18. 기준 문서: [PROJECT.md](../PROJECT.md).

## 최신 수정 — 시작 메뉴 글자 잘림

사용자 화면에서 설명 잘림과 무기 제목 겹침이 발견되어 GUILayout 자동 높이·순차 배치로 변경했다.
시작/일시정지/결과 메뉴에 적용했고 언어 버튼은 별도 줄이다. 부족한 높이는 스크롤로 처리한다.
컴파일과 검사 36개 통과. 배치 캡처 실패로 수정 화면 시각 확인은 아직이다.
다음 확인은 같은 화면 크기의 한국어 줄바꿈, 무기·펫 간격, 시작·상점·언어 버튼이다.

## 가장 중요한 사용자 지시

**게임을 먼저 다 만들고, MCP는 그 뒤에 진행한다.**
사용자는 기존 Unity 화면·조작을 확인했다고 답변했다. 기존 화면 확인 대기는 끝났다.
MCP 기능 추가·보고서·분석 실험을 다음 작업으로 잡지 않는다.

## 사용자가 아직 플레이하지 못한 것 — 돌아오면 반드시 안내한다

사용자가 명시적으로 요청한 사항이다. 아래를 **항목별로** 테스트해 달라고 말한다.
"확인했어"는 그 시점 빌드에 대한 것이므로, 이후 추가분까지 확인한 것으로 간주하지 않는다.

1. **강화 선택 화면 (0.2.0)** — 처치 5회 / 약 9초면 뜬다. 사용자가 확인한 빌드에는 없었다.
2. **무기 3종 (0.3.0)** — 펀치·화살·레이저. 화살 조작은 0.9.0에서 바뀌었다(아래 9번).
3. **보스 (0.4.0)** — 120초 등장. 붙었다 빠지는 리듬이 되는지. 레이저로 잡히는지.
4. **펫 3종 (0.5.0)** — Bori의 감속이 눈에 보이는지, Coco의 회복 주기가 답답하지 않은지.
5. **레이저 조준** — 모바일에서 드래그 없이 누르고만 있으면 빔이 직전 방향에 멈춘다. 어색한지 확인.
6. **상점·저장 (0.6.0)** — 판이 끝나면 코인이 쌓이는지, 게임을 껐다 켜도 남는지,
   Bori(320)·Coco(520) 해금이 유지되는지. 중도 종료로는 코인이 안 들어오는 게 납득되는지.
7. **한국어 UI (0.7.0)** — **글자가 네모로 깨지지 않는지가 제일 중요하다.**
   IMGUI 기본 폰트에 한글이 없어 OS 폰트로 대체하는데, PC에서는 맑은 고딕으로 되지만
   **Android는 확인 전이다.** 한국어 문장이 카드·버튼 폭을 넘치지 않는지도 봐야 한다.
   시작 화면 오른쪽 아래 버튼으로 한국어 ↔ English 전환이 된다.

8. **스프라이트 (0.8.0)** — 적이 100마리 겹쳤을 때 종류가 구분되는지.
   드로우 콜을 5분의 1로 줄였는데 실제 프레임이 나아지는지도 폰에서 봐야 한다.

9. **활 당기기 (0.9.0)** — 당겼다 놓는 감각이 맞는지. 최소 당김 0.25가 너무 크거나 작지 않은지.
   모바일에서 당김 반경이 엄지에 맞는지, 게이지가 손가락에 가리지 않는지.

10. **새 아트 (0.10.0)** — 플레이어·펫·적 외형과 숲 배경이 보이는지, 상점 초상화와 글자가 겹치지 않는지, 적이 많을 때 구분되는지 확인.

Android APK는 0.1.0이 마지막이다. 위 전부 들어 있지 않다.

- 게임 검사 36개 통과. 별도 프로젝트 복사본에서 실제 Unity 컴파일·9개 에셋 임포트·8종 512px 확인·렌더링 완료.

- 제작 프롬프트·적용 위치·한계: docs/art-direction.md.
- 새 아트의 Play 화면/상점 배치/적 다수 구분/Android 성능은 사용자 확인이 필요하다.
- 기존 아트 설명과 버전별 미검증 항목은 아래 역사 기록으로 남긴다.

## 최근 게임 변경 (0.9.0) — 활 당기기

사용자 지적: "화살은 클릭하면 나가지네? 당겨서 슉 하면 나가도록. 조이스틱처럼"

- 이동 조이스틱과 같은 제스처다. 누른 지점이 기준, 끌어당긴 방향이 발사 방향, 거리가 세기다.
- `arrowMinDraw`(0.25) 미만이면 **발사되지 않고 쿨다운도 안 돈다.** 툭 누르는 것은 발사가 아니다.
- 넘기면 `arrowMinPower`(0.55)~1.0 사이로 피해와 속도가 함께 비례한다.
- PC도 마우스를 누른 지점부터 당긴다. 커서 위치 조준은 펀치·레이저만 유지.
- 화면 게이지와 실제 발사가 `CombatWorld.DrawPower` **같은 함수**를 쓴다. 어긋날 수 없다.
- 검사 36개 통과.

**당김 수치(0.25 / 0.55)는 감각으로 검증되지 않았다.** 사람이 만져 본 뒤 조정한다.

## 다른 PC에서 테스트하려면

게임 저장소만 있으면 된다. 실험실 저장소는 필요 없다.

1. `git clone https://github.com/jjjGi/pet-them` — **저장소 전체**를 받는다.
   `game/Packages/manifest.json`이 `file:../../packages/com.petthem.combat-core`를 참조하므로
   game 폴더만 복사하면 열리지 않는다.
2. Unity Hub에서 Unity **6000.3.24f1** 설치. Android까지 보려면 Android Build Support도 함께.
3. Unity 계정 로그인 후 Personal 라이선스 활성화.
4. Hub에서 저장소 안의 **game** 폴더를 프로젝트로 추가.
5. 메뉴 **PET THEM > Create or open prototype scene** → Play.

.NET SDK는 검사를 돌릴 때만 필요하고 플레이에는 필요 없다.
저장 파일과 플레이 기록은 기기별로 따로 생기므로, 다른 PC에서는 코인이 0부터 시작한다.

## 이전 게임 변경 (0.8.0) — 스프라이트

- `game/Assets/Scripts/Art.cs`가 모든 스프라이트를 코드로 생성한다. 이미지 파일 없음, 라이선스 문제 없음.
- **손으로 그린 아트가 아니다.** 최종 아트 스타일은 여전히 미정이다.
- 종류마다 실루엣이 다르다. 색만으로는 무리가 겹치면 구분이 안 되기 때문이다.
- 얼굴·귀를 텍스처에 구워 **생물 하나 = 렌더러 하나**로 만들었다. 이전에는 5개였다.
  적 100마리 기준 렌더러 500개 → 100개.
- `Art.Pixels`는 원시 픽셀을 돌려준다. 에디터 없이 PNG로 뽑아 확인할 수 있고, 본 것이 그대로 들어간다.
- 펀치 이펙트가 링으로 바뀌면서 **보이는 원과 실제 사거리가 일치**하게 됐다. 이전에는 판정이 더 넓었다.

진짜 아트로 바꾸려면 `Art.Creature`가 생성 대신 로드한 Sprite를 돌려주면 된다.
이 파일 밖에서는 픽셀이 어떻게 만들어졌는지 모른다.

## 이전 게임 변경 (0.7.0) — 한국어 UI와 다국어 구조

- 화면 문자열 전부를 `game/Assets/Scripts/Texts.cs` 한 곳으로 모았다. 화면 코드에 리터럴이 없다.
- 언어 추가 = Texts.cs에 갈래 하나 추가. 기본값은 기기 언어, 시작 화면 버튼으로 전환.
- `UpgradeChoice`에서 Title/Description을 제거했다. 공용 코어는 플레이어용 언어를 갖지 않는다.
- 한글 폰트는 OS 폰트 대체로 해결했다. 폰트 파일은 라이선스 때문에 저장소에 넣지 않았다.
- 번역 누락은 검사가 잡는다(`default`로 떨어지면 열거형 이름이 나오도록 만들었다).

**Android에서 한글이 보이는지는 확인 전이다.** 실기기에서 가장 먼저 볼 것.

## 이전 게임 변경 (0.5.0) — 펫 3종

- 무기와 함께 펫도 판 시작 전에 고른다.
- Mochi 공격형(피해 100%) / Bori 제어형(45%, 감속·밀치기) / Coco 지원형(30%, 회복·피해 경감).
- 강화 선택지가 무기와 펫 양쪽으로 갈린다. 공용 5 + 무기 2 + 펫 1 에서 3개를 뽑는다.

**보스가 실제로 잡힌다는 것이 확인됐다.** 9개 조합 중 3개가 제한 시간 전에 처치했다.

**레이저 봇 수치는 무효다.** 봇이 조준 벡터를 주지 않아 빔이 오른쪽에 고정된 채 싸운다.
레이저는 의도적으로 자동 조준이 없기 때문이다. 레이저 평가용 봇 정책은 실험실 재개 시점의 작업이다.

## 검증 상태

- 게임 규칙 검사 36개 통과. 세부 내역은 docs/verification.md.
- 설치된 Unity 6000.3.24f1의 실제 UnityEngine DLL을 참조한 런타임 소스 컴파일 통과, 경고·오류 0.
  임시 검사 프로젝트는 experiments/unity-source-check/에 있으며 Git 제외다.
- 공통 코어 변경의 회귀 확인으로 실험실 main 검사 14개도 통과. 실험실 기능 개발을 재개한 것은 아니다.
- **0.2.0부터 0.9.0까지 어느 것도 Play 모드에서 사람이 확인하지 않았다.** 위 테스트 목록 참조.
- 0.1.0 APK에는 위 기능이 하나도 들어 있지 않다.
- 기존 Unity 에디터가 열려 있어서 같은 프로젝트에 배치 에디터를 추가로 실행하지 않았다.
