# PET THEM! 서버

게임과 **같은 전투 코어**를 참조하는 백엔드입니다. 판이 얼마짜리인지, 펫이 얼마인지를
클라이언트가 아니라 여기서 정합니다.

## 왜 이게 가능한가

`packages/com.petthem.combat-core`에 **UnityEngine 의존성이 없습니다.** 그래서 이 서버가
게임과 글자 그대로 같은 코드를 참조합니다.

- 보상 공식은 `CombatWorld.CoinsFor` **하나뿐**입니다. 게임이 결과 화면에 띄우는 숫자와
  서버가 지급하는 숫자가 같은 함수에서 나옵니다. 서버에 공식을 다시 쓰지 않았습니다.
- 펫 가격과 구매 규칙은 `PlayerProfile.PriceOf` / `Unlock` 그대로입니다.
- 판의 이변은 **시드에서 나옵니다.** 서버가 시드로 `CombatWorld`를 다시 만들어 그 판의
  `BalanceConfig`를 얻습니다. 어떤 이변이었는지를 클라이언트에게 묻지 않습니다.
- 수치도 게임이 쓰는 `game/Assets/Resources/balance-default.json`을 그대로 복사해 읽습니다.

## 실행

~~~powershell
dotnet run --project server/PetThem.Server
~~~

프로필은 실행 파일 옆 `petthem.db`(SQLite)에 저장됩니다. `--Database=경로`로 바꿀 수 있습니다.

## 저장

`IProfileStore`를 불러오기/저장하기 쌍이 아니라 **트랜잭션 경계**로 설계해둔 덕에,
메모리에서 SQLite로 옮기면서 **엔드포인트가 한 줄도 바뀌지 않았습니다.**
잠금이 트랜잭션이 됐을 뿐입니다.

**같은 판을 두 번 지급하지 않는 것이 DB 제약입니다.** `counted_runs`의 기본 키가
`(player_id, run_id)`이고, 지급 여부를 묻는 대신 `INSERT OR IGNORE`의 **삽입된 행 수가 답**입니다.
"이미 계산됐나?"를 묻고 계산하는 코드에는 두 질문 사이에 틈이 있습니다.

다만 트랜잭션 직렬화(`BEGIN IMMEDIATE`)와 기본 키가 **둘 다** 지키고 있고,
검사로는 어느 쪽이 실제로 버티는지 갈리지 않았습니다. 이중 방어지 측정이 아닙니다.

`schema_version` 테이블이 있어서, **더 새 서버가 쓴 파일을 구버전이 열면 거부합니다.**

## 검사

~~~powershell
dotnet run --project server/PetThem.ServerChecks -c Release
~~~

실제 서버를 OS가 고른 포트에 띄우고 **진짜 HTTP로** 때립니다. 핸들러를 직접 부르면 핸들러가
동작한다는 것밖에 증명하지 못하므로, 라우팅·모델 바인딩·상태 코드·인증 헤더까지 함께 봅니다.
테스트 프레임워크를 쓰지 않는 것은 `tools/CoreChecks`와 같은 이유입니다.

`scripts/check.ps1`이 이것도 함께 돌립니다. DB도 네트워크도 필요 없습니다.

## API

| | | |
|---|---|---|
| `GET` | `/health` | 살아 있는지 |
| `POST` | `/v1/session` | 게스트 세션 생성 → `{playerId, token}` |
| `GET` | `/v1/profile` | 프로필 (Bearer 필요) |
| `POST` | `/v1/runs` | 판 결과 제출 → 서버가 가격을 매김 |
| `POST` | `/v1/shop/unlock` | 펫 구매 → 서버가 가격을 매김 |

### 판 제출이 코인을 보내지 않는 이유

`RunSubmission`에는 획득 코인이 **없습니다.** 클라이언트는 무슨 일이 있었는지만 말하고,
그게 얼마짜리인지는 서버가 정합니다. 코인을 달라고 할 수 있는 클라이언트는 아무 액수나 달라고
할 수 있습니다.

### 멱등성

같은 `runId`는 **한 번만** 지급됩니다. 업로드 도중 신호가 끊긴 폰은 같은 판을 다시 보내고,
여러 번 보낼 수도 있습니다. 두 번째부터는 `alreadyCounted: true`와 함께 변하지 않은 프로필이
돌아옵니다.

## 지금 없는 것 — 정직하게

- **로그인이 게스트뿐입니다.** `POST /v1/session`을 부르면 새 플레이어가 생깁니다.
  신원 확인이 없습니다. Play Games 로그인이 이 자리에 들어갑니다 — 요청에 구글 server auth
  code가 붙고, 서버가 구글과 교환해서 그 계정에 묶인 플레이어의 토큰을 돌려줍니다.
  **응답 모양은 그대로**라서 이미 토큰을 저장해둔 클라이언트는 그대로 동작합니다.
- 세션 토큰에 **만료가 없습니다.** 한 번 받으면 영원히 유효합니다.
- **처치 수와 시간은 여전히 클라이언트의 말입니다.** 서버가 거르는 것은 모양뿐입니다 —
  음수 처치, 3분을 넘긴 3분 판, 없는 무기. **리플레이 검증이 이걸 닫습니다.**
  지금 보장되는 것은 "전투에 대해 거짓말해도 임의의 금액이 되지는 않는다"와
  "같은 판으로 두 번 못 받는다"입니다.
- HTTPS, 속도 제한, 배포 설정 없음.
